## G. Security / PHI

Only synthetic document content was processed in tests; no real provider call,
patient upload, clinical source read or client message was made for this task.
Scope is issued by the trusted PMC adapter after active source authorization.
The generic module does not accept a browser's scope as authority. Receipts contain
private opaque IDs but no names, raw document or clinical response text. No new
provider, production PHI transmission, auto-verification or interpretation policy.

## H–I. Limits and exclusions

This is the first **internal source-reading** capability, not the entire clinical
analysis engine or commercial NEXORA API. Google Document AI's new clinical
pipeline remains a separate validation path. Chat/voice remain on their existing
router; deep chat's multiple providers are not disguised as a completed migration.

Queue locking is not exactly-once provider billing. Multi-table writes are not
one transaction, failed-attempt receipts are not a complete durable provider
ledger, and unrelated concurrent document metadata updates are not serialized.
SDK continuation can make more physical calls than `logicalReadCalls`. The receipt
hash represents the actual processed attachment bytes, which may be downscaled.

No role promotion, password reset, generated impersonation session, bypass of
deployment protection, real-client send, new payment product or automatic model
learning was performed. External API authentication/revocation, quotas, tenant
storage and pricing need a separate accepted release.
