# Manual-review snapshots / Снимки ручных сверок

Status: local integration tested; NOT DEPLOYED. Base: canonical platform main `54ca208`, branch `codex/controlled-review-snapshots`.

## A. Before

The live-branch implementation stored `extraction-id + agreed/disputed + index`, decision and correction in `admin_notes`, but no row snapshot. Readback applied decisions by index even after reprocessing. The older root working tree did not contain that handler. This task uses a separate current-main worktree, preserving all unrelated root changes.

## B–C. Changes and files

- `lib/analytical-picture/review-snapshot.ts`: detached, content-hashed snapshot of the stored extraction row, extraction timestamp, document ID, collection and index. Digest is an integrity/version token, not an authorization credential or original-file hash.
- `queries.ts`: projects snapshot from server-read extraction, applies notes only when snapshot, token, document and exact displayed evidence ID match. Alternate views have distinct tokens. Historical index-only notes remain in the database but do not establish current confirmation. Notes are applied after evidence presentation to prevent an alternate-view review from confirming its primary view.
- `case-picture.ts`, `components/cases/CaseAnalyticalPicturePanel.tsx`: carry the version token to the existing review form.
- `actions.ts`: rechecks active staff state and Karen identity from verified Auth user (not mutable profile email); validates Case/document/evidence, rejects query errors and stale/missing token. Appends one existing `admin_notes` row containing original snapshot and correction together. Ignores client-supplied snapshot/reviewer fields. RU/EN stale-form error supplied.
- Tests: `evidence-review-snapshot.test.ts`, `evidence-review-action.test.ts`, `evidence-review-readback.test.ts`.

## D. Data/schema and concurrency

No migration, new table, trigger, RPC or production write. Snapshot and correction use one existing note INSERT, so they cannot be partially saved. No original extraction or clinical trust state is overwritten. If reprocessing happens after the action's read, its historical snapshot can still be saved, but it cannot apply to the later extraction on readback. This is snapshot-bound optimistic handling, not a database lock or serializable latest-version transaction. Simultaneous reviewers retain separate notes; existing newest-note selection remains.

## G–I. Safety, limitations and exclusions

Supabase skill informed the use of existing scoped storage and single-record save, without broader schema grants. Official [database function/security guidance](https://supabase.com/docs/guides/database/functions) consulted; no RPC was needed. Changelog markdown retrieval failed with unsupported content-type; no new Supabase feature/version assumed.

Snapshots contain clinical extraction text in the same staff-only existing note store. No external provider, training job, fixture export, credentials or real patient test data used. `training_eligible=false` and `source_verified_for_training=false` remain explicit. This adapter does not pretend the live document-only extraction is the more precise local EvidencePackage: page, geometry and original-file-byte hash are unavailable and remain unknown. Source-image adjudication/minimized export still required for benchmark admission.

Existing note ACLs are reused, not newly proven live. Auth and storage are mocked in integration tests; no new browser-mutation endpoint is added, Next Server Action origin protection remains existing infrastructure. No DB append-only ACL guarantee added. Historical notes without snapshots are not reconstructed or deleted; they may show pending in the current evidence UI. Their original correction text remains in storage, and historical-review browsing/reconciliation is separate pending work. No automatic learner, fine-tuning, methodology change, source reprocessing, production auto-verification or client response.

## J–L. Decision

Local snapshot save/readback integration CLOSED; live release and complete learning loop NOT CLOSED. User authorized scoped release preparation/publication. GO for isolated PR/preview and synthetic authenticated staging acceptance; NO-GO for production merge before staff-note access and RU/EN stale-form flow are verified against an isolated test environment. No claim that the live model already learns from reviews. After release, connect reviewed minimized corrections to the existing error-library/growth-gate foundation; never turn raw note confirmation into Gold automatically.
