# Продолжение голосовой команды в текстовом чате

Дата: 2026-09-11

## Что было

GPT-Live передавал сложную команду существующему ANHAM backend в той же
долгоживущей Next.js-функции. Закрытие голосового окна отменяло HTTP request,
а завершившийся после этого backend-ответ считался устаревшим и терялся.
Пользователь был вынужден держать оплачиваемое медиасоединение открытым во
время поиска, чтения данных или reasoning.

## Что изменено

- `session.delegation.created` получает серверный `live-background` exchange ID.
- Backend запускается с копией уже аутентифицированного server-side request без
  browser abort signal. Инструменты по-прежнему повторно проверяют аккаунт,
  роль, Case и существующие разрешения.
- Next.js `after()` удерживает уже начатую задачу после закрытия streaming
  response в пределах `maxDuration=300` текущей функции.
- Если голосовая сессия ещё открыта, результат возвращается в GPT-Live как
  раньше и произносится голосом.
- Если пользователь завершил звонок или соединение исчезло, результат
  идемпотентно сохраняется как один assistant message в существующей таблице
  `assistant_messages`, в том же profile/Case/conversation scope.
- Голосовая реплика пользователя остаётся `source=voice_transcript`; отдельная
  voice memory, таблица задач и копия бизнес-логики не создаются.
- Текстовый чат опрашивает существующий защищённый history endpoint только для
  ожидаемого exchange ID и автоматически добавляет готовый ответ.
- Во время `thinking` кнопка прямо сообщает, что голос можно завершить, а ответ
  придёт в чат. В этом состоянии браузер сразу освобождает WebRTC media вместо
  прежнего ожидания финальной статистики до 6,5 секунды.

## Security и данные

Профиль, роль и Case берутся только из исходной серверной аутентификации и
повторно проверяются существующим `runLiveBackend`. Exchange ID создаётся
сервером и ограничен форматом. История читается через прежний authenticated
endpoint с RLS/server ownership boundary. Секреты и raw audio не сохраняются;
новых API routes, grants и production migrations нет.

## Ограничение

Это продолжение переживает закрытие браузерного voice request, но остаётся
ограничено общим временем текущей Vercel-функции: не более 300 секунд от начала
голосовой сессии. Оно не является очередью, которая переживает redeploy или
полный runtime crash. Для задач дольше этого окна нужен отдельный durable
workflow с серверным job record и повторной проверкой полномочий.

## Приёмка

Проверить на аккаунте Anna:

1. Голосом спросить: «Сколько у нас оплат?»
2. Дождаться состояния «Анхам готовит ответ».
3. Нажать «Завершить голос — ответ придёт в чат».
4. Убедиться, что окно закрылось сразу, чат показывает фоновую работу, а ответ
   появляется в том же личном разделе без нового звонка.
5. Повторить в English и проверить, что Karen/Elena не видят денежную оценку.

Реальный microphone/provider acceptance остаётся пользовательской проверкой;
автотесты используют только синтетические данные.
