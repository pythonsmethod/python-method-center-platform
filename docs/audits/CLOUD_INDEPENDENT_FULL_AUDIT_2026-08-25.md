### PMC-01 — P0 — Оплата тарифа ни разу не превратилась в запись о платеже

- **Где:** `/payment` → Stripe Payment Link → `/api/stripe/webhook`; роль paid client; обе локали.
- **Ожидалось:** успешный checkout создаёт строку в `payments`, открывает
  `service_periods`, включает платный уровень ИИ и присылает команде
  «Оплата получена и записана автоматически».
- **Фактически:** в production нет ни одной записи об оплате тарифа. Все
  четыре строки в `payments` — архивный `test_access` по 3 USD, последняя от
  8 августа. Stripe при этом доставил семь успешных сессий, три ушли в
  ручную привязку, последняя — 24 августа.
- **Доказательство:**

  ```
  stripe_events
    checkout.session.completed                 5   last 2026-08-14 18:32
    checkout.session.async_payment_succeeded   2   last 2026-08-24 02:11
    payment_intent.payment_failed             22   last 2026-08-14 15:53

  payments
    paid / test_access / 3USD                  4   last 2026-08-08 19:50
    support_5_weeks, support_15_weeks          0

  notification_events
    payment_unmatched   sent    3   last 2026-08-24 02:11:10
    payment_failed      sent   22
    payment_recorded    skipped 1
  ```

- **Вероятная первопричина:** `productFromAmount()` (`lib/payments/stripe.ts`)
  признаёт платёж только при точном совпадении суммы — 144000 или 367500
  центов в USD; любая скидка, купон, частичная оплата или другая валюта дают
  `null`. Профиль ищется по `client_reference_id` или точному email
  плательщика. В обоих случаях код честно уходит в ручную привязку. Что
  именно сработало 24 августа, различает только дашборд Stripe.
- **Риск:** деньги списаны, кабинет пуст, период сопровождения не открыт,
  платный уровень ИИ не включён.
- **Рекомендация:** открыть три события `payment_unmatched` в Stripe и
  назвать точную причину; перестать выводить тариф из суммы (прописать
  продукт в `metadata` / `client_reference_id` платёжной ссылки, сумму
  оставить проверкой); разрешить допуск по сумме; показать очередь
  непривязанных платежей в `/admin`.
- **Регрессия и тесты:** средний риск, денежный путь. Юнит-тесты на
  разрешение продукта из metadata (включая её отсутствие на старых ссылках),
  тест идемпотентности при повторной доставке, сквозной прогон в Stripe test
  mode: успех, отложенный успех, отказ, возврат.

### PMC-04 — P1 — `/review` уезжает вбок на телефоне в русской версии

- **Где:** `/review`; `locale: ru`; 390×844 и 320×568; guest.
- **Фактически:** документ шире экрана — 442 px при 390 и 365 px при 320. На
  английской версии и на десктопе дефекта нет.
- **Доказательство и локализация причины:**

  ```
  /review ru 390×844 → {"innerWidth":442,"clientWidth":390,"scrollWidth":442}
  /review en 390×844 → {"innerWidth":390,"clientWidth":390,"scrollWidth":390}

  бисекция (стиль внедрён до первой раскладки):
    все дети body скрыты  → 390
    только header         → 390
    только footer         → 390
    только dock           → 390
    только main           → 442
    main, .hero скрыт     → 390   ← причина внутри .hero
  ```

  В `.hero` находится `<h1>` «Бесплатная предварительная оценка от Professor
  Python» при `font-size: 39px`. Слово «предварительная» не переносится
  (`overflow-wrap: normal`), его min-content шире 358 px контентной ширины, и
  Chrome на мобильном расширяет layout viewport до 442. Мобильный док и
  виджет Анхама затем наследуют эту ширину — поэтому наивный поиск
  «виноватого элемента» показывает их и уводит в сторону.

- **Проверенное исправление:**

  ```
  .hero h1 { overflow-wrap: anywhere }   → 390 ✓
  .hero h1 { font-size: 28px }           → 390 ✓
  h1,h2,h3,p { overflow-wrap: anywhere } → 390 ✓
  .hero h1 { hyphens: auto }             → 442 ✗ (не помогает)
  ```

- **Рекомендация:** `overflow-wrap: anywhere` заголовкам глобально — русский
  даёт длинные слова везде.
- **Тест-регрессия:** для каждого публичного маршрута × RU/EN × 390 и 320
  проверять `documentElement.scrollWidth <= clientWidth`. Такой тест поймал
  бы ровно два случая из 112.

## Безопасность и доступ

### PMC-06 — P2 — Открытая переадресация в `/auth/callback`

Все три копии `sanitizeNextPath()` (страница логина, `lib/auth/actions.ts`,
`app/auth/callback/route.ts`) отбрасывают только `//`. Путь `/\evil.com`
проходит проверку, а `new URL()` по стандарту трактует обратный слэш как
обычный:

```
new URL("/\\evil.com", "https://pythonmethodcenter.com").href → "https://evil.com/"
new URL("/\t/evil.com", …)                                    → "https://evil.com/"
new URL("/%2f%2fevil.com", …)                                 → остаётся на домене

app/auth/callback/route.ts:94
  NextResponse.redirect(new URL(nextPath, requestUrl.origin))
```

Срабатывание в бою не воспроизводилось: нужен валидный одноразовый код
подтверждения. Нормализация URL проверена и воспроизводится.

**Рекомендация:** одна общая функция вместо трёх копий; путь обязан
совпасть с `/^\/(?!\/)[A-Za-z0-9\-._~!$&'()*+,;=:@%\/?]*$/` — никаких
обратных слэшей, табов и переводов строки. Юнит-тест на список вредных путей.

## Интерфейс, доверие и находимость

### PMC-10 — P2 — Нет `hreflang` и `og:image`

Локаль хранится в cookie `pm-locale`, URL один и тот же. В `<head>` нет ни
одного `link rel="alternate" hreflang`, canonical указывает сам на себя.
Поисковик увидит только ту версию, которую ему отдали при обходе. Английский
контент, полностью переведённый, для поиска не существует. `og:image`
отсутствует — ссылка в мессенджере разворачивается без картинки.

```
link-теги на / (RU и EN): icon, apple-touch-icon, manifest, canonical
  hreflang: отсутствует
og: title, description, url, site_name, locale, type
  og:image: отсутствует
og:locale корректно переключается ru_RU ⇄ en_US
```

### PMC-11 — P2 — `/support` и экраны входа делят заголовок с главной

Свои `title` и `description` есть не у всех страниц. `/support`, `/login`,
`/recovery`, `/reset-password`, `/check-email`, `/onboarding` показывают
заголовок и описание сайта целиком. `/support` при этом перечислена в
`sitemap.xml` — в выдаче две страницы с одинаковым заголовком и описанием.

### PMC-12 — P2 — Фавикон весит 1,62 МБ

`/images/anham-master.png` (1024×1024, 1 695 667 байт) назначен одновременно
`icon`, `apple-touch-icon` и единственной иконкой манифеста, напрямую, мимо
оптимизатора. В манифесте нет размеров 192 и 512, которые ожидает установка
PWA. Иконки объявляются в `<body>` и переносятся в `<head>` инлайновым
скриптом.

**Рекомендация:** сгенерировать 32/180/192/512 (плюс ICO); исходники
`anham-master.png` (1,62 МБ) и `professor-python.png` (875 КБ) перевести в
WebP/AVIF.

### PMC-14 — P2 — После входа теряется вложенный маршрут

`/cabinet/documents`, `/cabinet/metrics`, `/cabinet/chess` и вложенные
