# AI Core — журнал миграции по фазам

Спецификация: [`AI_CORE_PROVIDER_INDEPENDENCE_V1.md`](./AI_CORE_PROVIDER_INDEPENDENCE_V1.md).

Её правило (§24): каждая фаза начинается с осмотра кода и заканчивается
отчётом, **следующая фаза не начинается без проверки человеком**. Этот файл —
то, что остаётся после каждой фазы.

## Фаза 0 — заморозка поведения

**Дата:** 9 августа 2026. **Функциональных изменений нет** — ни одна строка
рабочего кода не тронута. Добавлены только тесты и эта запись.

Смысл фазы простой. Дальше провайдеров будут вынимать из бизнес-кода и
ставить за общий интерфейс. Такая правка ломает не громко: не падает сборка,
а тихо меняется то, кого спросили первым или что увидит человек, когда одна
модель упала. Заморозка — это письменный ответ на вопрос «а как было
раньше», который иначе придётся вспоминать.

### Что сейчас есть — режимы

Пять режимов, `lib/assistant/router.ts`:

| Режим | Что делает |
| --- | --- |
| `auto` | Claude первым (если ключ есть), иначе GPT. При отказе — молча второй. |
| `best` | Оба отвечают параллельно, арбитр выбирает один ответ. Один ключ → сваливается в `auto`. |
| `claude` | Claude первым, **но с тем же переходом** на GPT при отказе. |
| `gpt` | GPT первым, с переходом на Claude при отказе. |
| `both` | Оба ответа рядом, подписанные. Режим сравнения для Карена. |

Кому какой режим достаётся (`app/api/assistant/client/route.ts`):

| Уровень | Режим | Лимит ответа | В минуту |
| --- | --- | --- | --- |
| гость | `claude` | 650 | 8 |
| зарегистрирован | `claude` | 700 | 20 |
| клиент с оплатой | `best` | 900 | 30 |

Плюс жёсткий потолок 40 сообщений в минуту с одного IP до всего остального.
Штабной маршрут (`app/api/assistant/staff/route.ts`) выбирает режим сам,
лимит 1500 (в режиме `both` — 1200), и **только там** ответ подписывается
именем модели.

### Что сейчас есть — модели

| Провайдер | Модель | Откуда |
| --- | --- | --- |
| Anthropic | `claude-opus-4-8` | `ASSISTANT_MODEL`, `lib/assistant/claude.ts` — жёстко в коде |
| OpenAI | `gpt-5.1` | `DEFAULT_OPENAI_MODEL`, переопределяется `OPENAI_MODEL` |

Адрес OpenAI переопределяется `OPENAI_BASE_URL`. У Anthropic такого нет —
SDK берёт адрес сам.

### Что сейчас есть — прямые вызовы провайдера

Спецификация (§7.3, фаза 4) требует довести это число до нуля вне адаптеров.
На день заморозки:

| Место | Вызовов | Зачем | Что будет, если Claude недоступен |
| --- | --- | --- | --- |
| `lib/assistant/router.ts` | 6 | сам роутер | это и есть точка выбора, её не убирают, а заменяют |
| `lib/cases/review-actions.ts` | 3 | два независимых чтения документов + финальный разбор | разбор не делается, человеку — «попробуйте через минуту» |
| `app/api/metrics/extract/route.ts` | 1 | перенос показателей в таблицу | значения не выдумываются |
| `lib/supplements/actions.ts` | 1 | подсказка по времени приёма | ошибка |

| `app/api/assistant/staff/route.ts` | 1 | сообщение **с файлом** | текст про `ANTHROPIC_API_KEY` |

Импорты SDK провайдеров уже сейчас есть только в `lib/assistant/claude.ts`
(Anthropic SDK) — OpenAI вызывается через `fetch`. То есть §5 нарушен не
импортами, а тем, что бизнес-модули зовут `askClaude` по имени.

**Почему файлы уходят прямо к Claude.** Не по предпочтению, а потому что в
`askOpenAi` вложений просто нет в сигнатуре. Это и есть работа фазы 3.

### Что сейчас есть — форма ответа

Три состояния, `AssistantResult`:

- `{ status: "ok", reply }`
- `{ status: "error", message }` — конкретная поломка;
- `{ status: "unavailable" }` — ключей нет.

Правило, которое легко потерять при переписывании: когда обе модели упали,
наверх идёт **`error`, а не `unavailable`** — конкретная причина полезнее
слов «не настроено». И ни при каком отказе не появляется текст, похожий на
ответ.

Разметка режима `both`: `— Claude —`, `— GPT —`, а если одна молчит —
`— GPT — сейчас недоступен, выше ответ одной модели.` Подпись победителя в
`best`: `· Ответил Claude (выбран арбитром как более сильный)`.

Новый файл фиксирует 19 утверждений: какие режимы существуют; кого
спрашивают первым; что переход на второго провайдера молчаливый; что третьей
попытки не бывает; что названный провайдер всё равно переходит на другого;
что отказ арбитра не стоит человеку ответа; что подпись модели появляется
только там, где её просили; и что **ни один режим не возвращает `ok`, когда
обе модели упали**.

### Проверено тем, что тесты ломались

Тест, который никогда не падал, не доказывает ничего. В код роутера по
очереди внесены три настоящие ошибки миграции, и каждая была поймана:

| Что подменено | Упало тестов |
| --- | --- |
| `auto` начинает с GPT вместо Claude | 1 |
| отказ первого провайдера окончателен (нет перехода) | 3 |
| при отказе арбитра человек получает ответ GPT вместо Claude | 3 |

После восстановления файла — 19 из 19 зелёные.

### Чего эта заморозка не гарантирует

Тесты держат **маршрутизацию**, а не качество моделей: провайдеры
подменены. И они не видят продакшн — здешние зелёные тесты уже не раз
расходились с живым сайтом. Проверка каждой следующей фазы — человек,
который пройдёт по сайту руками.

**Изменённые файлы:** `tests/router-behaviour.test.ts` (новый),

## §15 — имя модели видит только основатель

**Дата:** 9 августа 2026. Не фаза миграции, а решение основателя, которое
спецификация уже требовала в §15: «обычный человек общается с Анхамом, а не с
поставщиком». Раньше это соблюдалось для клиентов и не соблюдалось для
команды.

**Правило:** ни клиенты, ни Professor Python не знают, какая модель отвечает и
какой ответ арбитр счёл сильнее. Видит только основатель.

**Как сделано:**

- решение принимает сервер, а не браузер: `staffAssistantView()` в
  `lib/assistant/staff-provider.ts`. Спрятать переключатель было бы
  украшением — запрос всё равно несёт в себе `provider`, какой пожелает
  отправитель;
- команда получает тот же режим, что и раньше (`best` — две модели плюс
  арбитр). Пропадает только подпись победителя, качество ответа не меняется;
- `canSeeProviderNames()` в `lib/auth/require-founder.ts` **закрыт по
  умолчанию**: если `FOUNDER_EMAILS` не задан, имя модели не видит никто,
  включая администраторов. Пустая переменная окружения не должна тихо
  возвращать всё как было;
- тексты ошибок OpenAI больше не называют поставщика. Это была настоящая
  утечка к клиенту: «GPT перегружен» доходило до экрана человека, потому что
  маршрут отдаёт `message` как есть.

**Что нужно от основателя:** задать в Vercel `FOUNDER_EMAILS` со своей
почтой. Пока она не задана, переключателя не видит никто — включая её саму.
Эта же переменная закрывает кабинет основателя (`/admin/founder`), где модели
названы в строке расходов: без неё туда попадает любой администратор.

**Помощник больше не объясняет и устройство.** Раньше он продавал платный
уровень словами «связка сильнейших моделей: две дают ответ, третья выбирает
лучший». Компании не названы, но это то же самое, что убрано с экранов:
человека зовут доверять устройству, а не ответу, — и именно эту фразу он
потом цитирует, когда просит переключить его на конкретную модель. Вместо
неё сказано, что даёт уровень: ИИ знает путь конкретного человека. Плюс
прямой запрет в `lib/assistant/identity.ts` — не называть компании и модели
и не говорить, сколько их: убрать фразу мало, спрошенная напрямую модель
охотно расскажет о себе сама.

**Где имена остаются намеренно:** политика конфиденциальности
(`lib/legal/policy-content.ts`). Это не «кто лучше ответил», а «кто получает
ваши данные» — обязательное раскрытие, убрать его нельзя.

**Проверено:** `tests/provider-invisible.test.ts` — доступ к виду и
сканирование всех исходников `app/`, `components/`, `lib/` на имена
поставщиков в тексте, который видит человек. Список разрешённых файлов
короткий, у каждого записана причина. Проверено четырьмя подсаженными
утечками: имя в ошибке клиента, имя в вёрстке главной страницы, открытый
доступ при пустом списке, выбор модели из браузера в обход сервера — все
четыре пойманы. Плюс живой браузер: у команды переключателя нет, у
основателя есть.
