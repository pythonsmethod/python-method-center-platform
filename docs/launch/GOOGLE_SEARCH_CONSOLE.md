# Google: что нужно сделать руками

Со стороны кода всё готово: `robots.txt`, `sitemap.xml`, канонические
адреса, описание для поиска, отдельная страница о человеке. Ни одна из
этих вещей не заставляет Google прийти — она только делает так, чтобы
приход не был напрасным.

Остальное делается в аккаунте Google и в панели домена, куда у кода
доступа нет. Здесь — по шагам.

**Проверить это из среды разработки невозможно:** исходящий трафик
контейнера не пускают ни на google.com, ни на боевой домен. Всё, что
касается «видит ли Google сайт», может посмотреть только человек с
браузером.

---

## 1. Убедиться, что сайту есть что показать

Открыть в браузере и увидеть текст, а не ошибку:

- `https://pythonmethodcenter.com/robots.txt`
- `https://pythonmethodcenter.com/sitemap.xml`

В `sitemap.xml` должно быть десять адресов. `/shop` там нет намеренно:
страница просит себя не индексировать, пока в магазине нечего купить, и
вернётся в карту сайта с первым реальным товаром.

Если любой из двух адресов отдаёт 404 — дальше идти нет смысла, сначала
чинить это.

---

## 2. Search Console: добавить сайт

`https://search.google.com/search-console` → **Добавить ресурс**.

Предлагают два типа. Разница существенная:

| Тип | Что покрывает | Как подтверждать |
| --- | --- | --- |
| **Домен** (рекомендуется) | все поддомены, http и https, с www и без | только запись DNS |
| Префикс URL | ровно один адрес, как введён | DNS, HTML-тег, файл, Analytics |

**Домен** лучше: иначе `www.pythonmethodcenter.com` и
`pythonmethodcenter.com` — для Google два разных ресурса, и статистика
разъедется по двум отчётам.

### Подтверждение через DNS (для типа «Домен»)

Google покажет строку вида `google-site-verification=<длинный код>`.
Её нужно добавить как **TXT-запись** там, где обслуживается домен:

- если домен управляется в Vercel — **Project → Settings → Domains → DNS
  Records → Add**, тип `TXT`, имя `@`, значение — строка от Google;
- если у регистратора (GoDaddy, Namecheap, reg.ru) — в его панели DNS,
  раздел обычно называется «DNS Management» или «Записи DNS».

DNS обновляется не мгновенно: обычно минуты, иногда до суток. Если
Google говорит «не удалось подтвердить» — подождать час и нажать
«Проверить» ещё раз, не удаляя запись.

### Подтверждение через HTML-тег (для типа «Префикс URL»)

Этот путь уже подготовлен в коде. Google покажет тег вида
`<meta name="google-site-verification" content="ABC123..." />`.

Нужен **только код изнутри** `content`, без самого тега:

1. Vercel → Project → Settings → Environment Variables
2. Name: `NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION`
3. Value: `ABC123...` (только код)
4. Сохранить → **Deployments → Redeploy** (без редеплоя переменная не
   попадёт на сайт)
5. Вернуться в Search Console и нажать «Подтвердить»

Код публичный по своей природе — он виден в исходнике страницы у любого
сайта, который так подтверждается, и даёт доступ только к статистике
Google, ни к чему больше.

**Не удалять подтверждение после проверки.** Google перепроверяет его
периодически, и удалённая запись отбирает доступ к ресурсу.

---

## 3. Отдать карту сайта

Search Console → **Файлы Sitemap** → в поле ввести `sitemap.xml` →
**Отправить**.

Через несколько часов статус должен смениться на «Успешно», а рядом
появиться число обнаруженных страниц.

---

## 4. Попросить проиндексировать главные страницы

Карта сайта — приглашение, а не команда. Ускорить можно вручную:

Search Console → **Проверка URL** → вставить адрес → дождаться проверки →
**Запросить индексирование**.

Порядок важен, лимит — примерно 10–12 запросов в сутки:

1. `https://pythonmethodcenter.com/`
2. `https://pythonmethodcenter.com/professor`
3. `https://pythonmethodcenter.com/review`
4. `https://pythonmethodcenter.com/payment`

Остальные страницы Google найдёт сам по карте сайта.

---

## 5. Чего ждать и когда

| Когда | Что | Тревожно? |
| --- | --- | --- |
| сразу | подтверждение владения | — |
| часы | карта сайта прочитана | — |
| 2–7 дней | первые страницы в индексе | нет |
| 1–3 недели | сайт находится по названию | нет |
| 1–3 месяца | сайт находится по смысловым запросам | нет |

Статус **«Обнаружено — сейчас не проиндексировано»** — нормально для
нового сайта. Значит Google знает адрес и дойдёт до него позже. Пугаться
и удалять что-то не нужно.

### Как проверить своими глазами

В поиске Google:

- `site:pythonmethodcenter.com` — покажет, что вообще попало в индекс.
  Пусто в первую неделю — нормально.
- `Python Method Center` — по названию сайт должен находиться первым.
- `Professor Python Пашикян` — проверка, что страница о человеке видна.

## 6. Стоит сделать заодно

**Bing Webmaster Tools** (`bing.com/webmasters`) — пять минут, умеет
импортировать всё из Search Console одной кнопкой. Bing питает поиск
ChatGPT, а часть аудитории приходит оттуда.

**Google Business Profile — не подходит.** Он для бизнеса, который
принимает людей по адресу или выезжает к ним. Центр работает онлайн;
попытка завести карточку на адрес компании в Лос-Анджелесе закончится
отклонением или блокировкой.

**Чего делать нельзя:** покупать ссылки, регистрироваться в каталогах
«для SEO», заказывать «продвижение в топ за неделю». Для сайта о
здоровье это прямой путь к санкциям — Google относит такие темы к
категории, где проверяет источник строже всего.

---

## 7. Почему страница о профессоре важна для поиска

Google выделяет темы здоровья и денег в отдельную категорию и оценивает
их по тому, **видно ли, кто стоит за текстом**. Именно это на странице
`/professor` теперь и есть: настоящее имя, фотографии, биография,
образование, компания и адрес, прямо названные границы работы.

Отсюда практическое следствие: страница о человеке — не «страница про
нас для галочки», а главный аргумент сайта в глазах поиска. Всё, что её
усиливает (видео, где он говорит сам; ссылка на неё с главной), работает
и на доверие людей, и на позиции.
