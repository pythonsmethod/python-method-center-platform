# Письма подтверждения — настроить один раз

Занимает 30–40 минут. Программист не нужен. Делается в трёх местах:
Supabase, Vercel и в панели домена.

## Зачем

Подтверждение почты вернули: человек регистрируется, получает письмо,
нажимает в нём кнопку и попадает в кабинет.

Со стороны сайта путь уже выпрямлен — отдельная страница «Проверьте
почту» с кнопкой, открывающей нужный почтовый ящик, кнопкой «отправить
заново» и выходами на случай, если ничего не получается. Но **письмо
должно дойти и должно быть понятным**. Это настраивается здесь, и без
этого остальное бессмысленно.

Три вещи, которые ломают путь чаще всего, и все три — в настройках:

1. письмо не доходит, потому что отправляет встроенный SMTP Supabase;
2. письмо на английском, и человек не понимает, куда нажимать;
3. ссылка не работает, если письмо открыли на другом устройстве.

---

# ЧАСТЬ 1. Свой отправитель писем (20 минут)

Встроенный отправитель Supabase — для разработки. У него жёсткий лимит
писем в час, у отправителя нет репутации, и письма падают в «Спам» или не
уходят вовсе. **Это главная причина, по которой люди не могли войти.**

Нужен свой отправитель. Два варианта, оба бесплатны на наших объёмах.

## Вариант А. Resend — по шагам

Бесплатно до 3000 писем в месяц. Нам нужно несколько десятков.

### Шаг 1. Завести аккаунт (2 минуты)

1. Открыть **resend.com**, нажать **Sign up**.
2. Зарегистрироваться через Google или по почте. Подтвердить свой адрес,
   если попросят.

### Шаг 2. Добавить домен (2 минуты)

1. В меню слева нажать **Domains**.
2. Кнопка **Add Domain**.
3. В поле имени написать домен **без** `https://` и без `www`:

   ```
   pythonmethodcenter.com
   ```

4. Регион (**Region**) выбрать **eu-west-1 (Ireland)** — ближе к нашим
   людям, письма идут быстрее.
5. Нажать **Add**.

Откроется таблица из нескольких строк — это и есть DNS-записи. Не
закрывайте эту вкладку, из неё сейчас будем копировать.

### Шаг 3. Понять, куда класть записи (1 минута)

Записи кладутся туда, где домен управляется. Проверить:

- **Namecheap → Domain List → Manage**, посмотреть раздел **Nameservers**.
- Если там **Namecheap BasicDNS** — записи добавляем в Namecheap, вкладка
  **Advanced DNS**.
- Если там **Custom DNS** с адресами вида `ns1.vercel-dns.com` — домен
  управляется Vercel, и записи добавляем в **Vercel → проект → Domains →
  выбрать домен → DNS Records**.

Дальше шаги одинаковые, отличаются только названия кнопок.

### Шаг 4. Перенести записи (10 минут)

В Namecheap: **Advanced DNS → ADD NEW RECORD**. Для каждой строки из
Resend создать свою запись.

Обычно строк три или четыре:

| Что за строка | Тип в Resend | Зачем |
|---|---|---|
| `send` | **MX** | обратный адрес для отчётов о доставке |
| `send` | **TXT** (начинается с `v=spf1`) | разрешение отправлять от вашего имени |
| `resend._domainkey` | **TXT** (очень длинная, с `p=`) | подпись, по которой Gmail и Mail.ru узнают, что письмо не поддельное |
| `_dmarc` | **TXT** (`v=DMARC1`) | необязательная, но лучше добавить |

Правила, на которых спотыкаются:

- В поле **Host** пишется только левая часть — `send`, `resend._domainkey`,
  `_dmarc`. **Без** `.pythonmethodcenter.com` на конце: Namecheap
  дописывает домен сам. Если написать целиком, получится
  `send.pythonmethodcenter.com.pythonmethodcenter.com` и ничего не
  заработает.
- Значение копировать **целиком**, вместе с точками и знаками. Длинную
  строку с `p=` удобнее копировать кнопкой копирования в Resend, а не
  выделять мышью.
- У MX-записи есть отдельное поле **Priority** — поставить **10**.
- **TTL** оставить **Automatic**.
- Существующие записи, которые смотрят на Vercel (`A` на `@` и `CNAME` на
  `www`), **не трогать и не удалять** — иначе ляжет сайт.

### Шаг 5. Дождаться проверки (10–30 минут)

Вернуться в Resend, нажать **Verify DNS Records**. Статус домена должен
стать **Verified** (зелёный).

Если через полчаса всё ещё **Pending** — открыть запись в Namecheap и
сверить символ в символ. Чаще всего дело в дописанном домене в поле Host
или в потерянном куске длинной строки.

### Шаг 6. Ключ (1 минута)

1. В меню слева **API Keys** → **Create API Key**.
2. Имя: `supabase`. Permission: **Sending access**.
3. Нажать **Add**, скопировать ключ целиком — он начинается на `re_`.

> Ключ показывается **один раз**. Не закрывайте окно, пока не вставите
> его в Supabase. Потерялся — создайте новый, старый удалите.

### Шаг 7. Вписать в Supabase (2 минуты)

Настройки почты живут **не** в Project Settings, хотя туда тянет пойти
первым делом. Путь такой:

1. В узкой левой колонке — иконка **замка**, это **Authentication** (тот
   же раздел, где список Users).
2. В меню слева, блок **NOTIFICATIONS** → **Emails**.
3. Наверху страницы вкладка **SMTP Settings** (рядом с Templates).

Включить переключатель и заполнить:

```
Sender email: no-reply@pythonmethodcenter.com
Sender name:  Python Method
Host:         smtp.resend.com
Port:         465
Username:     resend
Password:     <ключ, который начинается на re_>
```

Username — это буквально слово `resend`, не ваша почта. Нажать **Save**.

> **Ящика `no-reply@pythonmethodcenter.com` заводить не нужно.** Адрес
> отправителя и почтовый ящик — разные вещи: Resend подтвердил домен, и
> этого достаточно, чтобы слать письма от любого адреса на нём. Ящик не
> существует, письма туда не приходят, и так и задумано — `no-reply`
> прямо говорит человеку, что отвечать бессмысленно. Поэтому в шаблоне
> письма ниже есть строка с адресом страницы поддержки: тому, кому нужна
> помощь, должно быть куда пойти.

## Вариант Б. Яндекс 360 для бизнеса

Если письма идут в основном на `mail.ru`, `yandex.ru` и `bk.ru`,
доставляемость у российского отправителя обычно выше. Заводится почта на
своём домене, дальше в Supabase указываются `smtp.yandex.ru`, порт `465`,
логин — почтовый ящик целиком, пароль — **пароль приложения** (не пароль
от аккаунта).

## Вписать в Supabase

**Authentication → Emails → вкладка SMTP Settings** → включить → вставить
данные своего отправителя → **Save**. Подробнее — в Шаге 7 выше.

## Про лимит писем

Как только свой SMTP включён, Supabase сама поднимает лимит до **30 писем
в час** — на фокус-группу этого хватает, трогать ничего не нужно. У Resend
на бесплатном тарифе свой предел, около сотни писем в сутки, так что
задирать лимит выше смысла нет.

Если понадобится — **Authentication → Rate Limits** (блок CONFIGURATION в
том же меню).

Там же, на странице SMTP, есть **Minimum interval per user** — сколько
ждать между двумя письмами одному человеку. По умолчанию 60 секунд; **30**
приятнее, потому что кнопка «отправить письмо ещё раз» перестаёт ругаться
на того, кто нажал её дважды.

## Как отличить пустое поле от заполненного

Supabase показывает в пустых полях серые подсказки — `noreply@yourdomain.com`,
`your.smtp.host.com`, `SMTP Username`. Это **не** значения: серый текст
означает, что поле пустое, введённое становится чёрным. Легко включить
переключатель, увидеть подсказки и решить, что всё уже заполнено.

И пока внизу горит зелёная кнопка **Save changes**, ничего не сохранено.

**Authentication → Sign In / Providers → Email** → включить **Confirm
email** → сохранить.

> Делать это **после** Части 1. Если включить подтверждение раньше, чем

# ЧАСТЬ 3. Адреса возврата (2 минуты)

**Authentication → URL Configuration**:

- **Site URL**: `https://pythonmethodcenter.com`
- **Redirect URLs** — добавить обе строки:

```
https://pythonmethodcenter.com/auth/callback
https://www.pythonmethodcenter.com/auth/callback
```

Если Site URL указывает не туда, ссылка из письма ведёт на `localhost` —
с телефона такую открыть невозможно в принципе.

# ЧАСТЬ 4. Русский текст письма (10 минут)

По умолчанию Supabase шлёт письмо на английском: «Confirm your signup».
Человек, который не читает по-английски, такое письмо закрывает.

**Authentication → Emails → Confirm signup** → включить **Custom email** →
в поле **Subject** вписать:

```
Подтвердите почту — Python Method
```

В поле с текстом письма вставить целиком:

```html
<div style="font-family: -apple-system, Segoe UI, Roboto, Arial, sans-serif; max-width: 480px; margin: 0 auto; padding: 24px; color: #1c1508;">
  <p style="font-size: 18px; margin: 0 0 16px;">Здравствуйте!</p>
  <p style="font-size: 16px; line-height: 1.5; margin: 0 0 24px;">
    Вы создали аккаунт в центре Python Method. Остался один шаг —
    нажмите кнопку ниже, и откроется ваш личный кабинет.
  </p>
  <p style="margin: 0 0 24px;">
    <a href="{{ .SiteURL }}/auth/callback?token_hash={{ .TokenHash }}&type=signup&next=/cabinet"
       style="background: #d4af37; border-radius: 8px; color: #1c1508; display: inline-block; font-size: 17px; font-weight: 700; padding: 14px 28px; text-decoration: none;">
      Подтвердить почту
    </a>
  </p>
  <p style="color: #6b6350; font-size: 14px; line-height: 1.5; margin: 0 0 8px;">
    Кнопка не нажимается? Скопируйте эту ссылку и вставьте в адресную
    строку браузера:
  </p>
  <p style="color: #6b6350; font-size: 13px; word-break: break-all; margin: 0 0 24px;">
    {{ .SiteURL }}/auth/callback?token_hash={{ .TokenHash }}&type=signup&next=/cabinet
  </p>
  <p style="color: #6b6350; font-size: 14px; line-height: 1.5; margin: 0 0 8px;">
    Если вы не регистрировались в Python Method, просто удалите это
    письмо — ничего не произойдёт.
  </p>
  <p style="color: #6b6350; font-size: 14px; line-height: 1.5; margin: 0;">
    Отвечать на это письмо не нужно — его отправляет робот. Нужна помощь?
    Напишите нам: <a href="{{ .SiteURL }}/support" style="color: #8a6d1f;">{{ .SiteURL }}/support</a>
  </p>
</div>
```

Так же — **Authentication → Emails → Reset password**. Subject:

```
Новый пароль — Python Method
```

Текст тот же самый, но с двумя отличиями: кнопку назвать **«Задать новый
пароль»**, а в обеих ссылках заменить

```
&type=signup&next=/cabinet
```

на

```
&type=recovery&next=/reset-password
```

## Почему именно `token_hash`, а не ссылка по умолчанию

Ссылка, которую Supabase подставляет сама, привязана к тому браузеру, где
человек нажал «Создать аккаунт». Зарегистрировался на компьютере, открыл
почту на телефоне — ссылка не срабатывает, и человек видит ошибку, ничего
не сделав неправильно. Это происходит постоянно, потому что почту читают с
телефона.

`token_hash` работает с любого устройства. Сайт умеет принимать обе формы
(`app/auth/callback/route.ts`), но письма лучше слать в той, что не ломается.

# ЧАСТЬ 5. Проверить (5 минут)

Зарегистрировать тестовый аккаунт на свою почту — подойдёт
`ваш.адрес+test1@gmail.com`, Gmail доставит его вам же, а для Supabase это
новый адрес.

Что должно произойти:

1. После кнопки «Создать аккаунт» открывается страница **«Проверьте
   почту»** с вашим адресом и кнопкой, открывающей ваш почтовый ящик.
2. Письмо приходит **в течение минуты**, по-русски, с золотой кнопкой.
3. Письмо во «Входящих», а не в «Спаме». Если в «Спаме» — DNS-записи из
   Части 1 не подхватились, проверьте статус домена в Resend.
4. **Откройте письмо на телефоне, а регистрируйтесь на компьютере** —
   это и есть тот случай, который ломался. По кнопке должен открыться
   кабинет на телефоне.
5. Нажмите ссылку из письма второй раз — должна открыться страница
   «Проверьте почту» с понятным объяснением, что ссылка уже
   использована, и кнопкой отправить письмо заново.

Если хоть один пункт не сошёлся — не запускайте на людях, сначала
почините. Это ровно те места, где фокус-группа теряется.
