# Что прогнать в Supabase — полная инструкция по шагам

Занимает 5–10 минут. Программист не нужен.

Всё, что нужно, — **один файл** и **два хранилища для файлов**.
Больше в Supabase делать ничего не надо.

Файл проверен на настоящей базе PostgreSQL 16: он запускается корректно,
запускается повторно без вреда и ничего не стирает.

---

## Коротко: что мы делаем

| Шаг | Что | Где |
| --- | --- | --- |
| 1–4 | Прогнать один SQL-файл | SQL Editor |
| 5 | Создать хранилище `client-documents` | Storage |
| 6 | Дать два правила доступа к нему | Storage → Policies |
| 7 | Перепроверить: 14 зелёных галочек | SQL Editor |

---

## Шаг 1. Открыть SQL Editor

1. Зайти на **supabase.com**, войти в аккаунт.
2. Открыть проект платформы (тот, что подключён к сайту).
3. В левом меню нажать **SQL Editor**.
4. Нажать **+ New query**.

## Шаг 2. Взять текст файла

Файл: **`supabase/ЗАПУСТИТЬ_В_SUPABASE.sql`**

На GitHub: репозиторий → папка `supabase` → этот файл → кнопка
**Copy raw file** (значок с двумя листочками справа сверху).

Копировать нужно **весь текст целиком**, от первой строки до последней.
По частям не надо — файл рассчитан на один запуск целиком.

## Шаг 3. Вставить и запустить

1. Вставить текст в окно запроса.
2. Нажать **Run** (или Ctrl+Enter / Cmd+Enter).
3. Подождать несколько секунд.

## Шаг 4. Посмотреть на таблицу проверки

Внизу появится таблица из **четырнадцати** строк. Так должно быть после
всех шагов:

| № | Что проверяем | Статус |
| --- | --- | --- |
| 1 | Таблица уведомлений (notification_events) | ✅ есть |
| 2 | Таблица событий Stripe (stripe_events) | ✅ есть |
| 3 | Защита от двойной оплаты (индекс payments) | ✅ есть |
| 4 | Поддержка без аккаунта (support_requests.contact_email) | ✅ есть |
| 5 | Код приглашения (profiles.referral_code) | ✅ есть |
| 6 | Таблица приглашений (referrals) | ✅ есть |
| 7 | Таблица токенов (token_transactions) | ✅ есть |
| 8 | Счётчики ИИ-помощника (assistant_usage) | ✅ есть |
| 9 | Функция счётчика (bump_assistant_usage) | ✅ есть |
| 10 | Сохранение переписки с ИИ (assistant_messages) | ✅ есть |
| 11 | Тестовый доступ за 3 $ (вид оплаты test_access) | ✅ есть |
| 12 | Адрес доставки клиента (profiles.delivery_address) | ✅ есть |
| 13 | Хранилище документов (Storage: client-documents) | ✅ есть |
| 14 | Хранилище голосовых (Storage: case-audio) | ✅ есть |

Строки 1–12 файл делает сам. Если хоть одна из них ❌ — прислать
скриншот, разберёмся.

Строки 13 и 14 — про хранилища файлов. Их этот файл **не создаёт**, он
только проверяет. Если там ❌ — идём в шаг 5.

---

## Шаг 5. Хранилище для документов клиентов

Нужно, если строка 13 показала ❌.

1. Левое меню → **Storage**.
2. Кнопка **New bucket**.
3. Имя (Name of bucket): **`client-documents`** — ровно так, маленькими
   буквами, через дефис.
4. **Public bucket — НЕ включать.** Хранилище должно остаться закрытым:
   там медицинские документы людей.
5. Если есть поле размера файла (File size limit) — поставить
   **52428800** (это 50 МБ).
6. Если есть поле разрешённых типов (Allowed MIME types) — вписать:
   `application/pdf`, `image/jpeg`, `image/png`, `image/webp`,
   `text/plain`.
7. **Create bucket**.

То же самое для `case-audio`, если ❌ в строке 14 (это голосовые
сообщения в переписке; тоже закрытое, публичным делать нельзя).

## Шаг 6. Два правила доступа к документам

Без них человек не сможет загрузить и открыть свои анализы.
Смысл простой: каждый видит только свою папку и ничью больше.

1. **Storage** → выбрать `client-documents` → вкладка **Policies**.
2. **New policy** → **For full customization** (создать вручную).

**Правило первое — читать своё:**

- Policy name: `client_documents_select_own`
- Allowed operation: **SELECT**
- Target roles: **authenticated**
- USING expression — вставить:

```sql
bucket_id = 'client-documents'
and array_length(storage.foldername(name), 1) = 3
and auth.uid()::text = (storage.foldername(name))[1]
```

**Правило второе — загружать своё:**

- Policy name: `client_documents_insert_own`
- Allowed operation: **INSERT**
- Target roles: **authenticated**
- WITH CHECK expression — вставить тот же текст:

```sql
bucket_id = 'client-documents'
and array_length(storage.foldername(name), 1) = 3
and auth.uid()::text = (storage.foldername(name))[1]
```

Правил на UPDATE и DELETE для клиентов создавать **не нужно**: человек не
должен иметь возможности подменить или стереть уже сданный документ.

Если в списке уже есть какое-то более широкое правило на чтение
`client-documents` (без проверки папки) — его надо удалить: оно открывает
чужие документы.

## Шаг 7. Перепроверить

Вернуться в **SQL Editor** и прогнать тот же файл ещё раз (повторный
запуск безопасен, это проверено). Теперь все четырнадцать строк должны
быть ✅.

Отдельно можно убедиться, что хранилище действительно закрытое:

```sql
select id, public from storage.buckets
where id in ('client-documents', 'case-audio');
```

В колонке `public` должно быть `false` у обоих. Если `true` — открыть
хранилище в Storage и выключить публичный доступ.

И что правила на месте:

```sql
select policyname, cmd from pg_policies
where schemaname = 'storage' and tablename = 'objects'
  and policyname like 'client_documents%';
```

Должно быть две строки: `client_documents_insert_own` (INSERT) и
`client_documents_select_own` (SELECT).

## Если появилось сообщение об ошибке

Сообщения со словом **NOTICE** — это не ошибки, а обычные пояснения
(«такое уже есть, пропускаю»). Их можно игнорировать, их будет много.

Настоящая ошибка — красная надпись со словом **ERROR**. В этом случае:

1. Не запускать ничего повторно.
2. Сделать скриншот целиком, вместе с текстом ошибки.
3. Прислать — разберёмся.

Ничего страшного при ошибке не произойдёт: Supabase выполняет такой файл
целиком или никак, поэтому база останется в том же виде, что и была.

---

## Чего в Supabase делать НЕ нужно

- Ничего не удалять руками из таблиц.
- Не делать хранилища публичными.
- Не выдавать ключ `service_role` никому и никуда, кроме переменных
  окружения на Vercel. Этот ключ открывает все данные всех клиентов
  в обход любых правил.

## Что останется после Supabase (это уже не здесь)

Чтобы оплаты записывались сами, нужен вебхук Stripe — он настраивается
в личном кабинете Stripe, а не в Supabase:

- адрес: `https://pythonmethodcenter.com/api/stripe/webhook`
- события: `checkout.session.completed`
- ключ подписи вебхука положить на Vercel как `STRIPE_WEBHOOK_SECRET`,
  секретный ключ Stripe — как `STRIPE_SECRET_KEY`

Пока вебхука нет, оплата проходит в Stripe, но на сайте в разделе
«Оплаты» остаётся пусто — именно поэтому не записался тестовый платёж
на 3 $.
