# Как прогнать SQL в Supabase — по шагам

Занимает 3–5 минут. Делается один раз. Программист не нужен.

Файл, который нужно запустить: **`supabase/ЗАПУСТИТЬ_В_SUPABASE.sql`**
(в этой же папке репозитория).

Файл проверен на настоящей базе PostgreSQL: он запускается корректно и его
можно запускать повторно — ничего не ломается и не стирается.

---

## Шаг 1. Открыть SQL Editor

1. Зайти на **supabase.com** и войти в свой аккаунт.
2. Открыть проект платформы (тот, что подключён к сайту).
3. В левом меню нажать **SQL Editor** (иконка с надписью «SQL»).
4. Нажать **+ New query** (новый запрос).

## Шаг 2. Скопировать текст запроса

Открыть файл `supabase/ЗАПУСТИТЬ_В_SUPABASE.sql` на GitHub:
репозиторий → папка `supabase` → файл → кнопка **Copy raw file**.

Или открыть его на компьютере и скопировать **весь текст целиком**, от первой
строки до последней. Частями копировать не нужно — файл рассчитан на один
запуск целиком.

## Шаг 3. Вставить и запустить

1. Вставить текст в окно запроса в Supabase.
2. Нажать **Run** (или Ctrl+Enter / Cmd+Enter).
3. Подождать несколько секунд.

## Шаг 4. Проверить результат

Внизу появится таблица из десяти строк. Должно быть так:

| Что проверяем | Статус |
| --- | --- |
| Таблица уведомлений (notification_events) | ✅ есть |
| Таблица событий Stripe (stripe_events) | ✅ есть |
| Защита от двойной оплаты (индекс payments) | ✅ есть |
| Поддержка без аккаунта (support_requests.contact_email) | ✅ есть |
| Код приглашения (profiles.referral_code) | ✅ есть |
| Таблица приглашений (referrals) | ✅ есть |
| Таблица токенов (token_transactions) | ✅ есть |
| Счётчики ИИ-помощника (assistant_usage) | ✅ есть |
| Функция счётчика (bump_assistant_usage) | ✅ есть |
| Сохранение переписки с ИИ (assistant_messages) | ✅ есть |

**Десять зелёных галочек — готово.** Ничего больше делать не нужно.

Если где-то стоит ❌ — прислать скриншот, разберёмся.

---

## Что делать, если появилось сообщение об ошибке

Сообщения со словом **NOTICE** — это не ошибки, а обычные пояснения
(«такое уже есть, пропускаю»). Их можно игнорировать.

Настоящая ошибка — красная надпись со словом **ERROR**. В этом случае:
1. Не запускать ничего повторно.
2. Сделать скриншот целиком, вместе с текстом ошибки.
3. Прислать скриншот — файл написан так, что повторный запуск безопасен,
   поэтому ошибка почти наверняка означает что-то одно конкретное, и это
   быстро чинится.

## Что именно этот запрос создаёт

**Часть 1 — запуск платформы.** Журнал уведомлений команде (чтобы было
видно, дошёл сигнал в Telegram или нет), защита от двойной записи оплаты
при повторном событии Stripe, и возможность писать в поддержку без
аккаунта.

**Часть 2 — реферальная программа.** Личный код приглашения у каждого
клиента и запись, кто кого привёл.

**Часть 3 — токены.** Журнал начислений и списаний. Баланс всегда равен
сумме записей, поэтому он не может «поехать»: каждое изменение видно.

**Часть 4 — защита ИИ-помощника.** Суточные счётчики сообщений: на одного
посетителя и на всех гостей вместе. Без них потолки расходов на ИИ не
работают. Адреса посетителей не сохраняются — только их хеш.

Ничего из этого не удаляет и не меняет существующие данные: запрос только
добавляет новые таблицы и колонки.
